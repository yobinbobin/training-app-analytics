# Training App Analytics - SQL + Python

Учебный проект по продуктовой аналитике тренировочного приложения.

**Все пользователи и события синтетические.** Здесь нет реального A/B-теста и реального роста конверсии. Цель проекта - показать навыки построения продуктовой воронки, SQL, Python и статистического анализа.

## Задача

Представим приложение, где пользователь регистрируется, смотрит план занятий, начинает и завершает тренировку. Нужно найти потери в воронке и показать, как сравнивать две условные версии интерфейса.

Воронка: регистрация -> просмотр плана -> начало тренировки -> завершение тренировки.

## Что реализовано

- Генерация 4 000 синтетических пользователей с фиксированным seed.
- SQL: LEFT JOIN, CTE, CASE WHEN, COUNT DISTINCT, GROUP BY и конверсии.
- Python: pandas, SQLite, проверка SQL-результатов, z-тест двух долей, 95% доверительный интервал.
- Визуализация конверсии по этапам воронки с matplotlib.
- Дизайн возможного реального A/B-теста, **не проводившегося** на пользователях.

## Запуск

Требуется Python 3.10+.

1. Установи зависимости: `python -m pip install -r requirements.txt`
2. Сгенерируй данные: `python generate_data.py`
3. Запусти расчеты: `python analyze.py`

Скрипты создадут файлы `data/users.csv`, `data/events.csv`, `figures/funnel.png` и `RESULTS.txt`. CSV и PNG не загружены в репозиторий: они воспроизводятся кодом.

## Результаты симуляции

| Метрика | Группа A | Группа B |
| --- | ---: | ---: |
| Регистрация | 2 000 | 2 000 |
| Просмотр плана | 1 649 | 1 703 |
| Начало тренировки | 950 | 1 096 |
| Завершение тренировки | 664 | 835 |
| Конверсия регистрации в завершение | 33,20% | 41,75% |

Разница B - A = **+8,55 процентного пункта**. В модельном z-тесте p-value = 2,33e-08, 95% доверительный интервал = [+5,56; +11,54] п.п.

**Ограничение:** в генераторе данных у группы B заранее задана более высокая вероятность переходов. Это иллюстрация анализа, а не доказательство того, что интерфейс B работает лучше в реальном продукте.
